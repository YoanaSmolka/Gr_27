------------------------------
## 1. Настройка Терминала на Mac 🖥️
Если вам когда-нибудь понадобится отредактировать внешний вид командной строки или починить опечатку:

* nano ~/.zshrc — открыть файл конфигурации терминала.
* source ~/.zshrc — применить изменения в терминале прямо сейчас (без перезапуска приложения).

Внутри редактора Nano:

* Ctrl + O затем Enter — сохранить изменения.
* Ctrl + X — выйти из редактора.

------------------------------
## 2. Работа со ссылками репозиториев (Remote) 🔗
Если Git выдает ошибку, что репозиторий не найден, или адрес указан неверно:

* git remote -v — проверить, к какому адресу привязан ваш текущий проект.
* git remote set-url origin https://github.com — изменить адрес репозитория на правильный.
* git remote remove origin — полностью удалить привязку к удаленному серверу.
* git remote add origin ССЫЛКА — привязать проект к GitHub с нуля.

------------------------------
## 3. Первая и последующие отправки кода (Push) 🚀

* git push --set-upstream origin main (или коротко git push -u origin main) — отправить ветку на GitHub в самый первый раз и связать её с сервером.
* git push — отправлять код во все последующие разы (короткая команда, когда ветки уже связаны).

------------------------------
## 4. Авторизация и Безопасность 🔒

* Вместо обычного пароля от GitHub при запросе в терминале всегда нужно вставлять Personal Access Token (токен доступа), который начинается на ghp_....
* git config --global credential.helper osxkeychain — команда, которая заставляет Mac запомнить ваш токен в «Связи ключей», чтобы не вводить его каждый раз.

------------------------------
## 5. Полезные команды для работы с файлами 📁

* cd .. — выйти из текущей папки на один уровень вверх.
* cd ~ — быстро перейти в домашнюю (главную) папку пользователя.
* rm имя_файла.json.swp — удалить обычный файл.
* rm -rf .git — полностью удалить скрытую историю Git из папки (используйте осторожно, только если случайно создали Git не в той папке, например, в корне компьютера).

------------------------------
## 1. Старт проекта (Начало работы)

* git clone <ссылка_на_github> — скачать существующий проект с GitHub на компьютер. Создает готовую папку, внутри которой Git уже настроен и привязан к серверу (команда git init здесь не нужна).
* git init — создать новый Git-проект в текущей пустой локальной папке.

------------------------------
## 2. Проверка статуса (Что происходит в проекте?)

* git status — главная команда разработчика. Показывает, какие файлы были изменены, какие добавлены, а какие готовы к сохранению.
* git diff — показать точные изменения в коде (какие именно строчки были удалены или добавлены) до того, как вы их сохранили.

------------------------------
## 3. Сохранение изменений (Коммиты)
Процесс сохранения всегда состоит из двух шагов: сначала мы «складываем файлы в коробку» (индексируем), а затем «запечатываем её» (делаем коммит).

* git add <имя_файла> — подготовить конкретный файл к сохранению.
* git add . — подготовить вообще все измененные и новые файлы в текущей папке.
* git commit -m "Осмысленное сообщение" — сделать коммит (сохранить снимок кода). В кавычках обязательно пишите кратко, что именно вы сделали (например: git commit -m "fix setup config").

------------------------------
## 4. Синхронизация с GitHub (Обмен кодом)

* git push — отправить ваши локальные коммиты на GitHub (чтобы их увидел преподаватель или коллеги).
* git pull — скачать свежие изменения с GitHub на ваш компьютер (например, если проект обновился на сервере или ваш коллега внес правки).

------------------------------
## 5. Работа с ветками (Branches)

* git branch — показать список всех локальных веток. Звездочкой будет отмечена та, в которой вы сейчас.
* git checkout -b <имя_новой_ветки> — создать новую ветку и сразу переключиться в неё (удобно, когда делаете домашку отдельно от основного кода).
* git checkout <имя_ветки> — просто переключиться на уже существующую ветку.
* git merge <имя_ветки> — влить изменения из указанной ветки в ту, в которой вы сейчас находитесь.

------------------------------
## 6. Отмена и исправление ошибок

* git restore <имя_файла> — сбросить все ваши незакоммиченные изменения в файле до исходного состояния (если вы написали плохой код и хотите вернуть как было).
* git log — показать историю всех коммитов в этом проекте (автор, дата и сообщения). Нажмите клавишу Q, чтобы выйти из этого режима.
